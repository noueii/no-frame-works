# App Structure Rules

Placement, wiring, and scaffolding rules for the Go backend. Pair with `patterns.md` (layer patterns) and the per-layer rubrics (`service.md`, `repository.md`, `handler.md`, `domain.md`).

## Folder Map

| Path | Purpose | Rules |
|------|---------|-------|
| `cmd/<bin>/` | Entrypoints (server, worker, CLI tools). One `main.go` per binary. | No business logic. Wire config, construct `App`, call into `webserver`/`worker`. |
| `config/` | Runtime config + `App` struct. | `App` holds shared deps (db, logger). Exposes `API()` for services. Does NOT expose `Repos()`. |
| `internal/app/services/api/` | Cross-service contract registry. Neutral package to break cycle. | Contains `PostAPI`, `UserAPI` interfaces + `Op` types + `Request` types. `Op` has `Request` (input) + state fields (e.g. `Post`). |
| `internal/app/core/<concern>/` | Cross-cutting primitives (`actor/`, `apperrors/`, `tx/`, ...). | Pure types used by multiple layers. No I/O (except `tx/`, which owns DB tx lifecycle). |
| `internal/app/core/apperrors/` | Six shared sentinels + typed error codes. | No per-service errors. All user-facing errors go through `apperrors.Validation/NotFound/Conflict/Forbidden/Unauthorized`. |
| `internal/app/core/tx/` | Transaction manager, context-threaded. | Accessed as `s.app.Tx()`. See `tx.md`. |
| `internal/app/domain/` | Consolidated domain types + pure methods. | No per-service domain packages. No `database/sql`, no `net/http`, no SDKs. |
| `internal/app/infrastructure/<adapter>/` | External SDK wrappers (e.g. `identity/` for Kratos). | Thin adapter over third-party client. Exposes a project-defined interface so services don't import vendor SDKs. |
| `internal/app/services/<name>/` | Service implementation. | Contains `api.go` (Service struct) + one file per operation. Implements `api.PostAPI`/`api.UserAPI`. |
| `internal/webserver/handler/` | HTTP handlers. | Thin. Holds `*config.App`. Calls `h.app.API().Service.Op(...)`. |
| `internal/webserver/middleware/` | HTTP middleware. | No business logic. Auth/logging/request-id only. |
| `internal/webserver/` (root) | Router setup, wiring. | **Wiring lives only here.** No init funcs, no per-service wiring. |
| `internal/worker/` | Asynq job handlers. | Same discipline as handlers: thin, use `app.API()`. |
| `repository/<entity>/` | go-jet data access. | One function per file. `toModel`/`toDomain` private to the package. Domain-in, domain-out. |
| `generated/` | oapi-codegen + go-jet output. | **Never hand-edit.** Regenerated by `make openapi` / `make jet`. |

## File Structure

```
services/
├── api/
│   ├── post.go    # Request types + Op types + PostAPI interface
│   └── user.go    # Request types + Op types + UserAPI interface
├── post/
│   ├── api.go           # Service struct, implements api.PostAPI
│   ├── create_post.go   # CreatePost method
│   ├── get_post.go      # GetPost method
│   ├── update_post.go   # UpdatePost method
│   ├── delete_post.go   # DeletePost method
│   ├── list_posts.go    # ListPosts method
│   ├── list_all_posts.go # ListAllPosts method
│   └── repository.go    # PostRepository interface
└── user/
    ├── api.go
    ├── get_user.go
    ├── increment_post_count.go
    └── repository.go
```

## Op Structure

Ops live in `services/api/` and have two parts:

```go
// services/api/post.go
type CreatePostRequest struct {
    Title    string
    Content  string
    AuthorID string
}

type CreatePostOp struct {
    Request CreatePostRequest
    // state fields (populated by service)
}

type GetPostOp struct {
    Request GetPostRequest
    Post    *domain.Post  // state populated by service
}
```

Handlers set `Request`. Services set state fields.

## New Service Scaffold

Creating service `foo` requires:

```
services/api/
  foo.go     # Request types + Op types + FooAPI interface

services/foo/
  api.go         # Service struct { app *config.App; repo FooRepository }
  create_foo.go  # one operation per file, file name matches operation
  get_foo.go
  ...

repository/foo/
  find_by_id.go  # one function per file
  insert.go
  update.go
  model.go       # toModel / toDomain (private)
  
internal/webserver/handler/
  foo.go         # thin handler; one method per endpoint
```

Wire in `internal/webserver/` — nowhere else.

## Service Shape

```go
type Service struct {
    app  *config.App
    repo FooRepository
}

func New(app *config.App, repo FooRepository) *Service { ... }
```

Two fields, always. Constructor takes both.

## Cross-Service Access

- **Allowed:** `s.app.API().Other.Op(...)` — go through the target service's API.
- **Forbidden:** `s.otherRepo.X(...)` — direct cross-service repo access. No `Repos()` accessor.
- **Forbidden:** importing another service's internal symbols.

## Wiring

- Single site: `internal/webserver/` (wireModules function).
- No `init()` functions for registration.
- No per-service `Wire()` helpers.
- Construction order: repos → services → register on `app.api`.

## Errors

- Use `github.com/go-errors/errors` everywhere — never `fmt.Errorf`, never stdlib `"errors"`.
- Wrap with `%w`: `errors.Errorf("service.post.CreatePost: validate: %w", err)`.
- Use `apperrors.Validation/NotFound/Conflict/Forbidden/Unauthorized` for user-facing errors.
- Error codes from `apperrors/codes.go` — typed constants like `CodePostTitleRequired = "post.title_required"`.

## Generated Code

- `backend/generated/` is rewritten by codegen. Editing it is always wrong.
- If a change is needed, edit the source (`openapi.yaml`, jet schema, migrations) and re-run `make`.

## File Naming

- One service method per file. File name matches operation: `create_post.go`, `get_post.go`.
- Not `execute.go`, not `service.go` (except root `api.go`).
- Test files: `<file>_test.go` next to the code.

## Smell Checklist

Stop if you're about to:
- Adding a field to `Service` beyond `app` + `repo`.
- Creating `services/<foo>/domain/` — domain is consolidated in `internal/app/domain/`.
- Writing `fmt.Errorf` or importing stdlib `"errors"` — use `github.com/go-errors/errors`.
- Calling a repo from a handler.
- Importing `oapi.*` in a service or `domain.*` in a handler.
- Editing anything under `generated/`.
- Adding an `init()` that registers a service.
- Adding `Validate()` methods on Ops — validation is inline in service methods.
